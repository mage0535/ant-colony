# 外部来源获取与接入策略

## 目标

在进入更深的 P-1 接缝验证前，先统一四类外部来源的获取方式，避免不同协作者各自采用不同路径，导致：

- 目录结构不一致
- 依赖来源不一致
- 后续交接难以复现
- P-1 验证结果不可比较

当前涉及的外部来源：

1. OpenVort
2. Hermes Agent
3. Memory Sidecar
4. gbrain

---

## 当前环境结论

基于当前组件级探针：

- OpenVort：当前环境中不可直接 import
- Hermes：当前工作区未发现本地源码目录
- Memory Sidecar：当前工作区未发现本地目录
- gbrain：`http://localhost:8787` 不可达

因此当前最需要先统一的是：

**这四类来源到底以什么方式进入 `./` 工作区。**

---

## 总体原则

### 1. 项目工作区优先可复现

所有协作者都应能通过读取 `./README.md`、`./AGENTS.md` 和相关脚本，在不同电脑上得到一致的接入方式。

### 2. 优先选择“对连续开发最友好”的接入方式

不是哪个方式最省事就用哪个，而是优先考虑：

- 跨电脑可复制
- 路径稳定
- 文档可描述
- 后续可交接

### 3. 对四类来源分别处理，不强行统一

四类来源可以采用不同策略，不要求全部用 pip、全部用 subtree 或全部用 Docker。

---

## 分来源建议

### OpenVort

#### 当前建议

优先顺序：

1. `pip 安装 + 明确版本`
2. `如 pip 不可控，再考虑源码接入`

#### 原因

- M1 当前主要想拿的是通道壳和接入层能力
- 如果能通过 pip 拿到稳定版本，接入成本最低
- 没必要一开始就把整个 OpenVort 仓库搬进当前工作区

#### 当前要求

- 一旦决定 pip 方案，要把安装命令、版本约束和验证方式写入脚本和文档
- 如果 pip 方案不可用或不稳定，应升级为源码接入方案

#### 当前结论

- 当前环境下 `pip index versions openvort` 未找到可用分发
- 因此下一步优先级已从 `pip` 方案转向源码接入方案

---

### Hermes Agent

#### 当前建议

优先顺序：

1. `源码 vendor / subtree`
2. `外部路径引用` 只作为临时验证，不作为长期方案

#### 原因

- 我们当前真正需要的是其共享 agent engine / loop 结构
- 后续大概率要抽取、裁剪、封装
- 这种情况下，源码可见比单纯安装包更重要

#### 当前要求

- 建议优先在 `./external/hermes/` 下落稳定位置
- 后续所有“可抽取性”验证都围绕同一份源码做

---

### Memory Sidecar

#### 当前建议

优先顺序：

1. `源码 vendor / subtree`
2. `如已有成熟安装包或固定脚本，再补安装链路`

#### 原因

- 当前阶段更重要的是记忆边界、目录隔离和后续接入方式
- 需要确认多目录安装、独立 state.db、个人/项目边界
- 这更适合基于明确源码或固定安装脚本验证

#### 当前要求

- 先明确来源与落点
- 建议优先在 `./external/sidecar/` 下落稳定位置
- 再决定是否通过安装脚本为测试目录批量安装

---

### gbrain

#### 当前建议

优先顺序：

1. `Docker / 本地服务启动`
2. `如当前机器无 Docker，则先记录阻塞并等待可运行环境`

#### 原因

- gbrain 更像一个运行中服务，而不是单纯代码引用
- 当前探针结论已经表明它不可达
- 如果没有可运行服务，就无法继续做真实接口验证

#### 当前要求

- 明确当前是否必须依赖 Docker
- 如果当前机器不适合跑 gbrain，就在文档中标明“需换环境验证”

---

## 当前推荐落地方式

为了不阻塞 M1 路线，建议先采用下面这版统一策略：

| 来源 | 当前推荐方式 | 当前目标 |
|---|---|---|
| OpenVort | `源码接入（当前 pip 方案不可用）` | 验证通道与基础接入壳 |
| Hermes | `./external/hermes/` | 验证 loop 可抽取性 |
| Sidecar | `./external/sidecar/` | 验证记忆体边界与多目录安装 |
| gbrain | `服务启动` | 验证基础接口可达性 |

---

## 当前不建议的做法

1. 每位协作者自己找一份外部源码临时放本机路径
2. 通过机器相关绝对路径引用外部项目
3. 一部分人用 pip，一部分人用本地 clone，但没有文档说明
4. 不记录版本、不记录来源，直接开始接缝开发

---

## 后续动作建议

### 第一优先级

确定这四类来源的获取方式。

### 第二优先级

把获取方式写成：

- 文档
- 脚本
- 验证入口
- 登记表

### 第三优先级

按来源分别推进 P-1 深验证。

---

## 一句话结论

当前阶段最需要的不是继续扩写骨架，而是先统一：

**OpenVort 怎么拿、Hermes 怎么落地、Sidecar 怎么落地、gbrain 在哪里跑。**
