# Ant Colony 企业 AI 助手使用总入口

本文档是公司知识库中的总入口页，供全体员工、部门负责人、知识库维护人员统一查阅。

当前系统的使用原则只有一条：

- 员工直接在企业微信里和 AI 助手对话
- AI 助手在后台调用知识库、文档、组织权限和其他企业能力

补充原则：

- 普通员工不自行创建或配置 BOT
- 企微 / 飞书 / 钉钉 BOT 由平台统一开通或由管理员在平台中辅助开通
- 员工只负责搜索、打开和使用

## 你应该先看哪一份

### 1. 第一次开始使用

请先阅读：

- [企业微信 AI 助手激活说明书](./wecom-ai-assistant-activation-guide.md)

适合：

- 第一次找不到机器人
- 不清楚怎么开始对话
- 不知道怎么确认自己已经激活成功
- 不清楚员工和管理员分别该做什么

### 2. 日常功能使用

请阅读：

- [企业微信 AI 助手功能与操作说明书](./wecom-ai-assistant-feature-guide.md)

适合：

- 想知道机器人能做什么
- 想知道每项功能怎么一步步操作
- 想知道上传文件、生成文档、搜索资料的标准方法

### 3. 知识库建设与管理

请阅读：

- [企业知识库分级建设与管理说明书](./knowledge-base-operations-guide.md)

适合：

- 需要把内容录入个人、项目、部门、公司知识库
- 需要按权限管理知识条目
- 需要维护知识库质量、查重、清理、升级归档

### 4. 知识库后台管理

适合：

- 部门负责人
- 项目负责人
- 公司管理员
- 知识库管理员

当前后台辅助入口：

- `GET /knowledge/manage`
- `GET /knowledge/user`

说明：

1. `/knowledge/manage` 适合管理员使用
2. `/knowledge/user` 适合员工直接管理自己权限范围内的知识库
3. 普通员工仍以企业 IM 机器人为主
4. 页面会按企业 IM 用户身份对应的组织架构和权限显示可见范围、可写范围和可操作按钮

### 5. 平台机器人统一开通

适合：

- 部门负责人
- 公司管理员
- 兼职 IT

当前平台入口：

- `GET /admin/console`
- `GET /platform/bots/manage`

用途：

1. 统一接管企微 / 飞书 / 钉钉 BOT 凭据
2. 由平台写入运行时配置
3. 统一维护显示名称、可见范围和权限能力
4. 检查缺少字段、当前进程环境变量和是否需要重启

推荐优先使用：

- `/admin/console`

原因：

1. 该页面通过企业 IM 用户身份和短期签名令牌校验管理员权限
2. 页面集中包含 Bot 开通、公司说明书导入、知识库入口、运行验证
3. 比单独的 `/platform/bots/manage` 更适合小白管理员按步骤操作

管理员审核开通状态时，应确认：

1. 平台状态为“启用”
2. 平台接管为“是”
3. 缺少配置为空
4. 当前进程缺少环境变量为空
5. 下一步提示已经进入“可继续做消息链路测试”

普通员工不需要进入这个页面，也不需要自己创建机器人或配置回调。

管理员访问链接由系统生成，形式为：

- `/admin/console?platform=wecom&user_id=企业IM用户ID&admin_token=短期签名令牌`

管理员进入页面后按以下顺序操作：

1. 先看“总览”，确认身份已验证
2. 打开“平台通道接入”
3. 逐字段填写对应平台的凭据
4. 点击“保存并接管”
5. 查看“是否需要重启”和“下一步”
6. 打开“员工助手开通”
7. 输入同事的企业 IM 用户 ID
8. 点击“开通并通知员工”
9. 打开“运行验证”确认端口和环境变量状态
10. 回到企业 IM 私聊和群聊中测试企业 AI 助手是否正常回复

员工助手开通说明：

1. 这里不是给每个员工创建一个完全独立的企业微信机器人
2. 正确模式是员工侧统一看到“企业 AI 助手”，后台自动使用应用通知、Bot 前台、群聊 @、文档/待办 MCP 等通道
3. 企业微信场景下，系统会尝试向员工直接发送统一欢迎消息，员工可直接回复该消息开始使用
4. 飞书和钉钉在没有真实账号时会保留为模拟/待联调状态

知识库管理页面：

- `/knowledge/manage`
- `/knowledge/user`

该页面会按企业 IM 用户权限自动展示可见知识和可操作按钮，支持：

1. 查询本人有权限访问的知识
2. 新增个人、项目、部门、公司级知识
3. 编辑有写权限的知识
4. 删除有写权限的知识
5. 将知识升级/复制到其他范围
6. 导入公司级说明书
7. 上传文档文件并立即解析、索引到对应知识库
8. 按组织目录查看公司、部门、项目、个人知识范围和权限状态

## 使用前先明确三件事

### 1. 激活不是注册

当前版本没有额外注册页面。

只要你在企业微信里成功和 AI 助手发起第一次对话，并收到正常回复，就表示你已经激活成功。

### 2. 聊天是主入口

普通员工的主入口是企业微信聊天窗口，不是后台管理页面。

大多数日常工作都应优先通过以下方式完成：

- 直接给 AI 助手发消息
- 在群里 `@AI 助手`
- 上传文件后继续发送要求

### 3. 权限不是手工写死的

知识库和资料调用不是“谁会搜谁都能看”。

当前系统按组织架构和空间范围控制读取权限，主要分为：

- 个人
- 项目
- 部门
- 公司

谁能看、谁能维护，以系统当前同步到的组织关系和空间成员关系为准。

## 当前稳定建议

- 日常问答：直接发消息给 AI 助手
- 群内协作：在群里 `@AI 助手`
- 文档分析：先上传文件，再立即发送要求
- 模板成文：先上传模板，再发送生成要求
- 知识搜索：明确写出关键词、主题词、文件名、制度名
- 正式入库：按知识库分级说明执行，不要把所有资料都直接丢到公司级

## 2026-06-24 后的当前规则：自动接管与自动权限

### 企业 AI 助手平台通道接入

员工侧只看到一个“企业 AI 助手”。管理员不需要先理解或手动填写 `bot_id`、`bot_secret` 等技术字段；后台会根据能力自动使用应用通知、Bot 前台、群聊 @、文档/待办 MCP 等通道。

当前管理台会按下面顺序自动采集已有配置：

1. 当前服务环境变量
2. 服务器配置文件 `infra/.env.wecom`
3. 历史平台配置
4. 管理员在高级配置中补录的一次性凭据

正常操作是：

1. 打开管理员控制台
2. 查看平台状态
3. 点击“确认自动接管企业微信”
4. 如果页面提示仍缺少凭据，再由管理员展开“高级配置”补录

普通员工不需要创建企业微信机器人，也不需要填写回调 URL、Token 或 AESKey。

### 知识库管理

知识库管理入口为：

- `/knowledge/manage`
- `/knowledge/user`

从管理员控制台点击“打开知识库管理页”会携带管理员身份自动进入。员工入口由系统生成，形式为：

- `/knowledge/user?platform=wecom&user_id=企业IM用户ID&user_token=短期签名令牌`

知识入库范围不再要求管理员或员工手动填写 `owner_type` 或 `owner_id`。系统会根据企业 IM 通讯录中的组织架构和权限自动决定：

1. 公司管理员默认写入公司知识库
2. 部门负责人可管理对应部门知识库
3. 项目成员按项目空间权限管理项目知识库
4. 普通员工默认写入个人知识库

企业 IM 通讯录、部门、负责人或管理员权限变化后，系统会在权限识别时自动按 TTL 刷新组织架构；管理员也可以在知识库管理页点击“同步组织架构”立即刷新。

公司说明书不是独立项目，它们只是公司知识库范围下的普通文档，统一通过知识库管理页查看、编辑、删除和维护。

飞书和钉钉使用同一入口，只需要把 `platform` 改为 `feishu` 或 `dingtalk`。当前没有真实飞书/钉钉租户时，可通过本地模拟数据验证页面、权限和上传流程。

### 企业 IM 前端指令入口

企业微信 Bot 当前不依赖固定菜单。员工和管理员可以直接给 Bot 发送指令，由系统自动生成短期签名链接。

常用指令：

1. `打开知识库`
2. `知识库管理`
3. `上传文档入库`
4. `打开管理员控制台`
5. `进入后台`
6. `菜单`
7. `帮助`
8. `入口`

权限规则：

1. 普通员工发送“打开知识库”会收到 `/knowledge/user` 链接
2. 管理员发送“打开管理员控制台”会收到 `/admin/console` 链接
3. 非管理员请求管理员控制台时，系统会提示没有管理员权限
4. 飞书和钉钉后续可把同样入口挂到机器人菜单或互动卡片上，底层仍复用同一套链接生成逻辑

### 三端当前一致状态

当前三端已经统一的内容包括：

1. 同一套入口命令词
2. 同一套签名链接生成逻辑
3. 同一套管理员/普通用户权限判断
4. 同一套知识库和后台入口 URL 结构
5. 同一套飞书菜单 / 钉钉卡片 payload 生成逻辑
6. 飞书 / 钉钉收到“菜单 / 帮助 / 入口”后，会直接返回结构化入口卡片

当前三端还存在的实现差异：

1. 企业微信仍以文本链接为主，不依赖固定菜单
2. 飞书和钉钉已经具备结构化菜单/卡片 payload，并且收到菜单指令时会直接发送结构化入口卡片；是否把它们真正挂成平台原生菜单，还取决于真实租户配置
3. 飞书和钉钉文件消息当前已支持两级处理：
   - 有真实 `file_key` / `downloadCode` 时，优先走平台文件下载和统一解析链路
   - 缺少真实下载元数据时，退回“文件占位文本”统一链路
4. 企业微信仍然是唯一已经完整打通真实文件下载、模板生成和文件回推的端

### 企业办公工作流助手

当前系统已经内置四类可直接触发的工作流助手：

1. 审批跟踪助手
   适合问法：
   - `帮我跟踪一下付款审批进度`
   - `这个审批卡在哪一步`

2. 会议组织助手
   适合问法：
   - `安排一次部门会议`
   - `帮我整理会议议程`

3. 制度 / 周报起草助手
   适合问法：
   - `帮我起草一个车间通行管理制度`
   - `根据这周工作整理周报草稿`

4. 工单分析助手
   适合问法：
   - `分析工单 WO-1001 的异常`
   - `看一下这个工单为什么延迟`

这些助手会自动组合审批、日历、会议、文档、知识库和样板业务系统能力，并把结果沉淀到记忆和知识库中，便于后续继续追问和复用。
## 企业 AI 助手文档与待办能力

管理员控制台提供“文档/待办能力”页签，用于配置企业 AI 助手背后的企业微信“文档”和“待办”MCP 能力。员工侧仍统一叫企业 AI 助手；该页面只保存 StreamableHttp URL 到服务器配置文件，不会把 apikey 写入 GitHub 代码、公开说明书或前端源码。

配置步骤：

1. 在企业微信机器人配置页打开“文档”可使用权限，复制 StreamableHttp URL。
2. 在企业微信机器人配置页打开“待办”可使用权限，复制 StreamableHttp URL。
3. 打开管理员控制台，进入“文档/待办能力”页签。
4. 分别粘贴“企业 AI 助手文档能力”和“企业 AI 助手待办能力”的 StreamableHttp URL。
5. 点击“保存 MCP URL”。
6. 如果页面提示需要重启，重启 dashboard、gateway、wecom-bot 服务。
7. 点击“发现 MCP 工具”，确认文档和待办均显示“已配置”且可发现工具。

启用后企业 AI 助手可调用的典型能力：

1. 文档：新建企微在线文档、写入 Markdown 内容、创建智能文档、追加表格数据。
2. 待办：创建待办、查询本人待办、更新企业 AI 助手创建的待办、删除企业 AI 助手创建的待办、按姓名搜索待办参与人。
3. 常见问法示例：
   - `帮我新建一份项目周报文档`
   - `把这几条内容整理成智能文档`
   - `帮我创建一个明天下午 3 点前完成的待办`
   - `查一下我本周有哪些待办`

安全要求：

1. StreamableHttp URL 中的 `apikey` 关联机器人和用户个人信息，只能保存在服务器环境变量或 `infra/.env.wecom`。
2. 不要把 URL 复制到 GitHub、公开文档、截图、群公告或普通聊天记录中。
3. 如果 URL 已泄露，应在企业微信机器人权限页面重置配置，并在管理员控制台重新导入。
4. 管理员页面展示 URL 时只显示脱敏结果，用于确认已配置状态。
