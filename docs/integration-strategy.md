# 外部项目集成策略

## 目标

明确 `ant colony` 对外部项目的吸收原则，避免后续开发中出现：

- 因为某个项目有现成功能就提前强接
- 为追求复用率而牺牲当前阶段验证速度
- 多位协作者对“现在该集成什么”理解不一致

当前原则：

**按阶段、按目标、按层次选择性吸收，不做四个项目的全量同步融合。**

---

## 当前涉及的四类外部来源

1. OpenVort
2. Hermes Agent
3. Memory Sidecar
4. KMM / 知识采集体系

---

## 总体策略

### 当前应坚持的判断标准

只有当某个外部项目的某一部分能力同时满足下面两个条件时，才应在当前阶段引入：

1. 能直接缩短当前阶段的验证路径
2. 不会明显增加当前阶段的集成复杂度

如果只满足“功能很好”，但不满足“适合当前阶段”，则推迟到后续阶段。

---

## 分项目吸收建议

### 1. OpenVort

#### 当前阶段优先吸收

- 企业微信 / 飞书接入壳
- 通道层思路
- Dispatcher 路由思路
- 可复用的管理入口思路

#### 当前阶段不优先吸收

- 全量插件能力
- 全量后台管理逻辑
- 重型 UI 或前端定制

#### 当前角色定位

**企业接入壳**

---

### 2. Hermes Agent

#### 当前阶段优先吸收

- 共享 agent engine 思路
- loop 结构
- 思考 / 工具调用 / 结果返回的基础链路

#### 当前阶段不优先吸收

- 全量上游复杂能力
- 自学习闭环
- 复杂 delegate 体系的完整实现

#### 当前角色定位

**共享 agent 引擎核心**

---

### 3. Memory Sidecar

#### 当前阶段优先吸收

- 分层记忆体设计思路
- 个人 agent 独立记忆边界
- 目录隔离方向

#### 当前阶段不优先吸收

- 全量复杂记忆栈
- 深度自动化安装链路
- 一开始就强依赖完整 sidecar 运行方式

#### 当前角色定位

**记忆体设计参照物**

---

### 4. KMM / 知识采集体系

#### 当前阶段优先吸收

- 个人 / 项目 / 组织知识域的划分思路
- 后续采集入口设计
- 知识沉淀方向

#### 当前阶段不优先吸收

- 30+ 采集工具全量接入
- 重型采集管线
- 知识运营层能力

#### 当前角色定位

**知识域与采集扩展位**

---

## 分阶段建议

### P-1 / M1

当前阶段重点：

- 从 OpenVort 拿通道入口
- 从 Hermes 拿共享引擎结构
- 从 Sidecar 拿记忆边界思路
- 从 KMM 拿知识域结构思路

这一阶段强调：

**借入口、借结构、借边界，不做全功能接入。**

### M2

可以逐步继续吸收：

- 更稳定的项目知识层
- 更真实的记忆体接入
- 更稳的项目总结、催办与规则参数化

### M3

可以逐步吸收：

- 多角色分析
- Worker Pool 扩展
- 更强目录隔离
- 组织同步能力

### M4 及以后

再逐步吸收：

- RAG 分层 ACL
- 知识采集管线
- 更多工具接入
- 更丰富模板体系

---

## 当前禁止的误区

### 误区 1

“某个项目有成熟能力，所以现在就应该接进来。”

当前规则：

**是否接入，不看它强不强，先看它是否服务当前阶段目标。**

### 误区 2

“四个项目既然都想吸收，那就同时把各自最强部分都接进来。”

当前规则：

**先让最小协作闭环成立，再逐步增加接缝。**

### 误区 3

“复用率越高越好。”

当前规则：

**当前阶段优先优化验证速度、架构可演进性和团队可维护性，而不是复用率本身。**

---

## 一句话结论

`ant colony` 对四个外部项目采取的是：

**分层取长、分阶段吸收、按目标选择性集成，而不是全量同步融合。**
