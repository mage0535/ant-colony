# 外部来源接入优先级

## 目标

在四类外部来源都尚未真正落地前，先明确：

- 先接哪个
- 为什么先接它
- 接完它之后再接什么

避免不同协作者在不同电脑上各自挑选不同来源先做，导致节奏失控。

---

## 当前建议顺序

### 1. OpenVort

**优先级：最高**

原因：

- 最直接服务 M1 的企业 IM 接入目标
- 最容易尽快验证“真实消息能不能进系统”
- 如果它接不上，当前很多网关与消息链路只能停留在内部模拟

当前目标：

- 确认获取方式
- 完成最小安装或接入
- 验证企微/通道路由壳是否可用

---

### 2. Hermes Agent

**优先级：第二**

原因：

- 当前共享 AgentEngine 的长期方向主要参考它
- 若后续无法稳定抽取或对齐 loop 结构，agent 内核路线需要尽早调整

当前目标：

- 确认源码落地方式
- 明确 loop 可抽取范围
- 判断是 vendor/subtree 还是外部引用

---

### 3. Memory Sidecar

**优先级：第三**

原因：

- 当前项目已经有了个人知识域 / 项目知识域边界
- 但真正的记忆体接入还未开始
- 它很重要，但对 M1 最小“消息进来 -> 草案确认”闭环不是第一阻塞

当前目标：

- 明确来源与落点
- 明确多目录安装和隔离验证策略

---

### 4. gbrain

**优先级：第四**

原因：

- 当前环境下 Docker 不可用，本地服务不可达
- 它更偏后续知识深度增强
- 在 OpenVort 和 Hermes 尚未落稳前，优先级可以后置

当前目标：

- 明确运行方式
- 确认是否需切换环境验证

---

## 当前顺序的核心逻辑

优先顺序不是按“哪个项目最强”排，而是按：

1. 对当前阶段目标的直接支撑程度
2. 是否会影响主链路架构判断
3. 当前环境下的现实可推进性

---

## 一句话结论

当前最建议的来源接入顺序是：

**OpenVort → Hermes → Memory Sidecar → gbrain**
